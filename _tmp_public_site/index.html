01 / Network

Ask for an outcome, not an address.

Software normally begins with a URL, vendor or model. TRUYN begins with a need. The network finds an eligible capability, checks whether the requester may use it, evaluates trust requirements and returns the minimum sufficient result.

01

Capability-first

Agents describe the job they need done. Providers advertise what they can do. Routing is based on capability instead of a hard-coded hostname.

02

Cryptographic identity

A TRUYN identity is independent of the current IP address. Requests, offers and results can be signed and verified.

03

Trust is contextual

A signature proves who signed. Provenance, evidence, freshness and independent attestations help determine whether a result should be trusted for a specific purpose.

04

BYOK by default

Your upstream AI credentials remain in your own runtime. An open protocol never implies permission to consume somebody else's paid provider capacity.

02 / How it works

A new logical network over the Internet that already exists.

TRUYN does not replace IP, fiber, Wi‑Fi or mobile networks. Agents connect through a TRUYN node; the network adds identity, capability discovery, authorization, routing, provenance and trust above existing Internet transport.

03 / Use

One network layer. Many forms of intelligence.

TRUYN is useful anywhere machines need to find, invoke, verify or exchange capabilities across organizational and vendor boundaries.

01 / AGENTS

AI agents

Let agents discover and invoke useful capabilities without maintaining a growing maze of one-off integrations.

02 / ENTERPRISE

Enterprise systems

Connect private intelligence through explicit authorization while preserving provider ownership and policy boundaries.

03 / EDGE

Robotics & edge

Move computation closer to sensors, machines or private data, then return only the necessary result or proof.

04 / VERIFY

Research & verification

Carry provenance, claims, attestations and trust evidence alongside machine-readable results.

What changes
+Fewer repeated prompts, tokens and duplicate inference operations
+Capability-aware routing instead of fixed model and API endpoints
+Reusable state, references, deltas and content-addressed objects
+Explicit authorization before private provider execution
+Trust context travels with the result instead of being reconstructed from scratch
04 / Developers

Run a node. Bring your intelligence. Start using the network.

The reference implementation is open source. Install it, create a cryptographic identity, connect your provider and use TRUYN from the CLI, an MCP-compatible agent or an HTTP bridge.

Provider secrets are read from your own environment. TRUYN stores the environment-variable name, not the credential value.

TRUYN / QUICK STARTNode.js ≥ 22
01 / install
git clone https://github.com/inn-media/truyn.git
cd truyn
npm install
02 / create identity
node cli/index.js init
03 / connect provider
export OPENAI_API_KEY='...'
node cli/index.js setup --provider openai --model YOUR_MODEL --test
04 / find and request a capability
node cli/index.js find reasoning.general --relay YOUR_RELAY
node cli/index.js need reasoning.general "Analyze this task" --relay YOUR_RELAY
05 / connect an MCP agent
node cli/index.js mcp --relay YOUR_RELAY
