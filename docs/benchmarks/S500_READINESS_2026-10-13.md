# Relay and provider capacity readiness

Status: candidate, not a measured paid benchmark or production acceptance.

The opt-in provider rate governor retries only HTTP 429, honours provider Retry-After with at most 10% jitter, and preserves per-call attempt, throttle and wait telemetry. It never replays a network failure or HTTP 5xx POST. Provider execution time is distinct from its bounded wait budget.

RPM/TPM buckets and remaining-budget headers are local advisory admission. Multiple processes must use a shared admission/cooldown coordinator; header observations cannot atomically reserve a deployment-wide budget. Optional admission and onThrottle callbacks provide that boundary. Returned telemetry stays attached to classified errors.

Relay configuration separates in-flight terminal reservations from the bounded terminal queue. Defaults preserve the previous limit and heartbeat interval. A capability index avoids scanning unrelated offers while retaining authorization, freshness and durable revocation checks. Authenticated RESULT metadata can deprioritize its own provider during upstream cooldown. Cooling and disconnected providers rank after eligible available providers; no price ceiling or ACL is bypassed.

Run node --test tests/s500-*.test.js tests/cloud-providers.test.js tests/relay-load-cost-routing.test.js and node benchmarks/s500-dry-burst.mjs for zero-inference verification. The burst holds every NEED until all ACKs arrive, then checks all signed RESULTs and provider identities. Synthetic timings do not predict paid-model latency. Keep measured acceptance on raw latency; ex-throttle latency is diagnostic only.

Thresholds, request TTL, queue depth, provider in-flight defaults and acknowledgement requirements remain unchanged. Deployment isolation and quota evidence belong to the consuming environment.
