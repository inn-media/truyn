Connect intelligence to intelligence.

Five first-party clients share one executable TRUYN conformance path: TypeScript, Python, Go, Java and .NET. TRUYN/1 remains draft; the SDK API contract is versioned separately.

Start with a relay

import { TruynLocalNodeClient } from '@truyn/sdk';

const client = await TruynLocalNodeClient.connect({
  relayUrl: 'https://relay.example'
});

const receipt = await client.need(
  'reasoning.general',
  { question: 'Hello from TRUYN' }
);

const result = await client.waitForResult(receipt.needId);

The same logical flow is implemented by the Python, Go, Java and .NET clients. Package coordinates below refer to the 0.1.0 alpha release line; registry availability is verified separately from source/build conformance.

Runtime surface

Identity

Each client creates an Ed25519 identity, signs TRUYN envelopes and verifies received signed events.

Discovery

Capability discovery uses the authenticated relay path and never promotes transport authentication into TRUYN authorization.

Execution

Publish OFFER, submit NEED, consume a verified NEED, return RESULT and preserve request/provider correlation.

Cancellation

Requester-owned direct NEED cancellation is a signed REVOKE and fails closed for unauthorized targets. Chain-stage cancellation is not generalized.

Streaming

Authenticated relay event streaming plus signed ordered PARTIAL deltas with correlation, idempotency and bounded backpressure where the runtime supports them.

Artifacts

Reference-oriented object/media payloads preserve MIME type, byte count, digest and provenance without implicit remote URL fetching.

Conformance means executable behavior

Release conformance starts one real local relay and independently runs the same two-node transaction in all five languages: registration → authorized OFFER → NEED → verified provider event → RESULT → verified requester result, plus direct NEED revoke/cancel. It is not a DTO-only or marker test.

Release integrity

Consumer distributions are built as npm tarball, Python wheel/sdist, Go module source bundle, Maven JAR/POM and NuGet package. Release verification checks package contents, Apache-2.0 LICENSE/NOTICE, exact source SHA, byte size and SHA-256 digest before publication.

Security boundary

SDK calls use the same TRUYN authorization path as every other interface. Remote protocol metadata cannot assign requester identity, provider ownership or billing responsibility. Late or cross-request RESULT/PARTIAL delivery fails closed, and SDKs do not implicitly fetch arbitrary artifact URLs.

Compatibility

SDK API contract v1 is the bounded developer-facing surface. It does not mean that the TRUYN/1 protocol itself is final. The 0.1.0 alpha package line is intentionally pre-stable while the protocol and ecosystem continue through compatibility gates.
