# TRUYN N-Series Roadmap

Status: **FOUNDATION DEFINED / EXECUTION NOT STARTED**  
Task: `truyn-n-series-foundation-260920-n0`

This roadmap takes N-Series from documentation to immutable measured evidence while preserving the two-repository boundary and cross-series isolation.

## Locked qualification model — applies to the entire N-Series

**Canonical model: `Frozen Candidate -> Branch Qualification -> Admission to Main`.**

This is a non-optional N-Series invariant until all N-Series testing is complete:

1. Expensive qualification belongs to a **frozen candidate SHA**, never to moving `main`.
2. While N qualification is running, `main` may move. Main movement **does not invalidate candidate evidence by itself** and **must not trigger an automatic full rerun**.
3. Admission compares **`BASE_SHA -> current main`**. If that drift does not touch an N-sensitive surface, expensive candidate evidence remains valid; only the small integration Admission Gate is required.
4. If drift touches an N-sensitive surface, requalify **only the affected N blocks**. A new live N run is permitted only when the affected-surface policy requires it.
5. Before merge/admission, build the integration candidate and **recompute N qualification fingerprints** on that combined state.
6. Historical GREEN on a branch SHA is **never sufficient merge or launch authority**. A small final Admission Gate on the combined state is mandatory.
7. Admission is bound to the exact `current main` SHA used to build it. If `main` moves again before merge/launch, admission is stale and must be recomputed; the expensive candidate run is still reusable unless N-sensitive analysis says otherwise.
8. Acceptance thresholds may not be weakened to avoid requalification.
9. The automatic N qualification manifest is mandatory evidence. It records `BASE_SHA`, candidate SHA, candidate fingerprint, changed files, N-sensitive surfaces and qualified blocks; admission records current-main SHA, integration fingerprint, affected surfaces/blocks and whether a live rerun is actually required.
10. Removal, weakening or bypass of this model requires explicit user authorization; ordinary cleanup/refactoring may not erase it.

Machine-enforced lock: `config/n-series-frozen-candidate-policy.json`. Verifier: `scripts/verify-n-series-frozen-candidate-policy.mjs`. Qualification/admission manifests are generated by `scripts/n-series-qualification-manifest.mjs` and consumed by the N-Series qualification/admission workflows.

## Required scenario order for first evidence generation

```text
SOVEREIGNTY → MARKETPLACE → TRUST-DECAY → SUSTAINED-CHURN
```

The order may overlap only when resource classification proves isolation. A long-running churn test must never block an unrelated benchmark by using a global benchmark lock.
