## Purpose

S-Series measures live semantic-node scale: the already-proven TRUYN network substrate combined with real heterogeneous AI-provider execution and semantic retrieval/economics. It is separate from D-Series network acceptance and from corpus/index-only Semantic Retrieval Scale Gate evidence.

A counted S-node is a real independently identified TRUYN runtime process with a real network endpoint/process, an eligible real provider assignment, server-side authorization before execution and attributable request/provider telemetry.

Required text-provider families remain GPT, Gemini, Grok, DeepSeek, Llama, Mistral and Kimi.

## Reuse-only architecture

S-Series does not define a second TRUYN network. Unless a measured defect requires an independently qualified repair, it reuses:

- TRUYN identity and signed envelopes;
- OFFER / NEED / RESULT semantics;
- current Node/Relay/adapter runtime;
- Class-D discovery/bootstrap/recovery substrate;
- `question + root CID → retrieval → provenance → minimal context → provider`;
- existing provider adapters and authorization boundary;
- append-only benchmark evidence policy.

S-Series must not use a benchmark run as a place to invent a new protocol, billing model, trust model or provider transport.

## Existing accepted foundations

S-Series starts from, but does not inherit PASS from:

- Class D-200 accepted and independently repeated network evidence;
- seven live provider families / seven-actor semantic evidence;
- semantic retrieval and corpus/index-scale evidence.

Each S-level requires its own immutable acceptance identity and durable evidence.

## Scenario families

The fixed scenario names remain:

- `ECON` — paired DIRECT vs TRUYN economics;
- `MIX` — vendor-mix invariance;
- `XBORDER` — multi-region / multi-cloud cross-border behavior;
- `CHAIN` — multi-hop heterogeneous provider chains;
- `CHURN` — provider/node loss, partition and revocation;
- `COST-ROUTING` — eligible-provider selection under bounded policy;
- `CONTENTION` — concurrent load/backpressure/cancellation;
- `LANG` — multilingual semantic behavior.

Thresholds, workload requirements and evidence rules remain canonical in `docs/benchmarks/SEMANTIC_SCALE_S_SERIES_CONTRACT.md`.

## Public / private ownership

Public `inn-media/truyn` owns reproducible architecture/methodology, public/reference runner surfaces, schemas/evaluator/conformance and sanitized durable evidence.

Private `inn-media/truyn-platform` owns managed cloud orchestration, real cloud topology, credentials/service identities/private endpoints/allowlists, quota/spend controls, raw telemetry, tenant state and proprietary managed optimization.

Dependency direction remains: private may consume accepted/versioned public surfaces; public never depends on private code.

## Isolation

S-Series uses independent workflow/concurrency/resource/evidence identities and must not mutate frozen D-Series launchers, evaluators or evidence. Shared R1 capacity is allowed only with attribution and active interference detection; R2 mutation is exclusive. If isolation cannot be proven, the run waits/fails closed rather than contaminating another series.
